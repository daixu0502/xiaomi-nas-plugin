# 小米 NAS Mihomo

## 功能说明

- 启动、停止和重启 Mihomo，切换运行模式及策略组节点。
- 导入和更新订阅、单条节点、代理提供者及规则提供者。
- 编辑并校验配置，查看运行日志，更新内核及 GeoIP / GeoSite 数据。
- 设置代理的本机或局域网访问范围，为 Docker 守护进程配置代理并检查生效情况。
- 测试节点的 HTTP 延迟与实际下载速度，查看最近结果并停止正在进行的测试。

## 如何使用

### 安装和更新

1. 在电脑的 **Ubuntu（WSL）终端**中，进入有 `manage.sh` 的插件文件夹，运行：

```bash
bash manage.sh
```

2. 输入 `1`，选择“安装 / 更新”，按提示输入 NAS 的 IP，再选择自己的账号。只有一个账号时会自动选择。
3. 等待提示安装成功，再到小米客户端的应用列表打开本插件。看不到时，退出客户端后重新打开。

更新也是这三步，已有配置会保留。需要先让电脑能用 root SSH 登录 NAS；还没开启时，见[SSH 开启步骤](../nas-root/README.md#开启-ssh)。

### 配置代理

1. 打开“Mihomo”，在“订阅”页导入自己的订阅地址，或添加单条节点。
2. 在“概览”页启动核心、选择运行模式并切换策略组节点。
3. 需要让局域网设备使用时，在“设置”页调整访问范围，并按页面显示的 NAS 地址及代理端口配置客户端。
4. 在“配置”页修改并校验配置，在“日志”页排查连接问题。
5. 需要让 Docker 拉取镜像使用代理时，在“设置 → Docker 守护进程代理”中应用设置，并检查进程加载状态和连通性。内核更新和 Geo 数据更新也在“设置”页操作。

内核、Geo 数据及订阅更新均在界面中操作；后台任务提交后可查看进度，重新打开页面可继续查看结果。

### 测试节点延迟和下载速度

1. 启动 Mihomo 核心，在“概览”页的“策略组”旁点击“节点测速”，打开测速弹出页面。页面会自动读取节点，也可点击“刷新节点”。列表包含配置内节点和订阅／手动导入的节点，同名但来源不同的节点分别显示。
2. 点击节点旁的“测延迟”，或点击“全部测延迟”。延迟使用 Mihomo 的节点测试接口访问 Cloudflare 的小型测试页面，显示 HTTP 请求耗时，单位为毫秒；连接失败或超时会明确提示。
3. 点击“测下载”并确认流量提示，测试该节点到 Cloudflare 测速服务的单连接下载速度。每次最多接收约 20 MiB，下载阶段约 8 秒，显示 Mbps、MiB/s、实际接收量和用时。达到流量上限时会标注，结果仅供比较参考，不代表线路的最高带宽。
4. 测试期间显示进度，可以点击“停止测试”。点击右上角关闭按钮或弹窗外的遮罩可关闭测速页面；已提交的任务仍会在 NAS 上完成，重新打开“节点测速”可读取进度和结果。取消时正在等待的连接可能需要几秒才能结束。

下载测试每次只测一个节点，会短暂运行一个仅监听本机的独立 Mihomo 进程；它只读取原有节点文件，完成后退出，不切换主核心的策略组或重启现有代理服务。测试流量由 NAS 发出，会消耗所选节点的流量，并受 NAS 网络、测速服务器和节点状态影响。

独立下载测速支持插件导入的订阅、手动节点及配置内节点；链式代理和自定义提供者目前仅提供延迟测试，下载按钮会说明限制。结果保存在插件官方临时缓存中，清理缓存后消失。每批延迟最多测试 200 个节点，同时最多连接 4 个；测速与配置、订阅及内核更新互斥，请等待完成或先停止测试再修改配置。

### 卸载

再次运行 `bash manage.sh`，输入 `2` 选择“卸载”，按提示选择账号并确认。

请用这个菜单卸载；只在小米客户端里删除，插件可能会自动恢复。手动指定账号等用法见[进阶说明](../docs/plugin-installation.md)。


### 工作台内页

订阅导入、手动节点导入、规则提供者导入及内核更新等区域直接显示，原有字段和操作保留。当前节点独占指标区一整行，长名称可使用完整横向空间。概览显示当前策略节点，核心有历史延迟采样时展示实际延迟；没有样本时仅显示节点名称。测速仍在独立弹窗中执行，不因打开概览自动发起下载测速。

## 注意事项

默认内核为 Mihomo v1.19.33（官方 ARM64 构建，Go 1.26.10）。安装和界面更新都会检查 Go 编译版本，拒绝早于 Go 1.26.10 / 1.27.3 的构建，防止重新引入 [CVE-2026-111943](https://pkg.go.dev/vuln/GO-2026-6809)。内核版本及固定摘要维护在 `src/files/core-release.sh`，插件版本仍只维护根目录 `INFO`。

受管配置仅引用非空节点提供者；首次添加或删除最后一个手动节点时会更新引用。运行日志按大小轮转，后台核心仍以自身 PID 交给系统服务管理。

- NAS 存储池需已挂载，目标用户需在小米客户端完成初始化；远程安装需能使用 root SSH 登录。
- 安装时需要联网获取并校验 ARM64 内核；安装包不是完整离线包。第三方许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
- 订阅地址和 API 密钥属于私密信息，请勿公开。代理端口以界面显示为准，多用户端口可能不同。
- 首次导入订阅会生成受管配置并备份原配置；修改已有复杂配置前建议自行备份。
- 应用或撤销 Docker 守护进程代理可能重启 Docker，影响整台 NAS 的容器；只查询状态不会重启。
- 内核更新和 Geo 数据变更可能短暂中断代理。若 Docker 正使用本插件的代理，卸载时会撤销该代理并重启 Docker。
- 使用安装脚本卸载会取消本插件的自动恢复登记；仅在应用市场删除时，恢复服务可能将插件补回。

- 关闭插件页面不会停止后台服务；通过页面主动停止后，恢复检查不会擅自重新启动。

页面右上角“外观主题”可选择跟随系统、浅色或深色，本地记忆选择；跟随系统时自动响应系统外观变化。

## 在线更新

电脑端点击左下角版本号，手机端点击底部版本号打开更新弹窗；发现新版本显示 `NEW`。打开插件时按缓存策略自动检查，也可手动点击“检查更新”。点击“立即更新”并确认后，后台自动下载、校验和安装，关闭页面仍会继续。完成后关闭插件窗口再打开。

“更新代理”支持 HTTP/HTTPS，例如 `http://127.0.0.1:7890`；按 NAS 账号在八个插件间共用，仅用于检查和下载安装包，不改变其他服务代理。认证用户名、密码分别填写，密码不会回传页面。修改后保存，启用代理时失败不会自动直连。

更新保留配置、任务、启用状态、已更新内核和 SSH 材料，验证失败自动回退。有下载、传输或关键任务时请稍后更新。首次使用需通过原安装器安装一次含在线更新组件的版本。签名发布与恢复细节见 [在线更新组件说明](installer/updater/README.md)。
