# 小米 NAS 下载中心

## 功能说明

- 使用 aria2 下载 HTTP / HTTPS / FTP / SFTP 直链，使用 qBittorrent 下载 BT 种子和磁链，无需 Docker。
- 选择当前用户的下载目录，管理队列、进度、速度、暂停、继续、重试和下载记录。
- 选择 BT 文件，配置并发、限速、做种偏好和 Tracker 列表及订阅。
- 更新两个下载内核，查看更新状态；按需接入 Openlist 或 AriaNg 等外部客户端。

默认 qBittorrent 内核为 5.3.0 / libtorrent 2.1.2，静态包包含 Qt 6.12.0、OpenSSL 4.0.3。安装下载会核对固定 SHA-256，已有任务、接口和配置在更新时保留。构建来源及许可见 [第三方组件说明](THIRD_PARTY_NOTICES.md)。qBittorrent、aria2 不使用 Go；系统 Python/OpenSSL 和 Docker 由 NAS 固件提供，更新本插件不等于更新这些系统组件。

## 如何使用

### 安装和更新

1. 在电脑的 **Ubuntu（WSL）终端**中，进入有 `manage.sh` 的插件文件夹，运行：

```bash
bash manage.sh
```

2. 输入 `1`，选择“安装 / 更新”，按提示输入 NAS 的 IP，再选择自己的账号。只有一个账号时会自动选择。
3. 等待提示安装成功，再到小米客户端的应用列表打开本插件。看不到时，退出客户端后重新打开。

更新也是这三步，已有配置会保留。需要先让电脑能用 root SSH 登录 NAS；还没开启时，见[SSH 开启步骤](../nas-root/README.md#开启-ssh)。

### 添加与管理下载

1. 打开“下载中心”，在“设置”页确认下载服务已启动，并选择默认下载目录。
2. 在“下载”页新建任务，粘贴直链或磁链，或选择电脑 / NAS 中的 `.torrent` 文件。
3. 选择下载目录；需要先选 BT 文件时，添加为暂停状态，等待元数据就绪后选择文件再继续。
4. 在任务详情中查看进度和文件列表，按需暂停、继续、重试或删除，在“记录”页查看历史结果。
5. 在“Tracker”页保存手动列表或订阅，按需启用每天自动更新，并核对实际应用结果。

### BT 种子缓存管理

在“设置 → BT 种子缓存”点击“查看 / 刷新种子”，查看下载中心自身 `var/metadata/<任务编号>/` 与 `var/qb-profile/qBittorrent/data/BT_backup/` 下自动生成的 `.torrent` 文件，显示大小、修改时间及任务占用状态；点击“预览 / 创建下载”选择种子内文件和下载目录，确认后才创建任务。

“删除种子缓存”仅删除无任务占用且无关联续传或写入状态的种子副本。所有现有任务（含暂停、失败及历史记录）、核心内的外部任务与 `.fastresume` 等恢复材料受到保护；服务未就绪时只可查看和预览。点击删除时会重新核对占用及文件是否改变，不依赖列表的旧状态。不操作任务记录、下载内容、断点数据或用户的 `data/.bt/`。

目录及文件保持原位；只管理当前用户的独立普通种子文件，不跟随链接。预览上限为 4 MiB，其他项目保留。种子管理只在手动加载时读取目录，不增加后台轮询。

### 外部客户端接入

在“设置”页查看实际接口地址、认证信息和监听状态。aria2 接入使用 HTTP JSON-RPC；qBittorrent 的对外接口用于 Openlist 兼容接入。

Openlist 的 `/opt/openlist/data/temp/` 临时目录会映射到当前 NAS 用户配置的下载目录，aria2 单任务和批量调用均支持。路径不能越出该用户的数据目录，也不能经过符号链接。qB 的新任务自动追加已配置的 Tracker，包含 Openlist 创建的任务；现有非私有任务在保存列表或启动服务时补齐，保留原有 Tracker。

修改接口密钥前先停止下载服务，保存后再启动，并同步更新外部客户端的认证信息。下载路径使用当前用户空间在 NAS 上的真实绝对路径；容器中的路径别名不能直接传给 NAS 原生下载核心。

### 卸载

再次运行 `bash manage.sh`，输入 `2` 选择“卸载”，按提示选择账号并确认。

请用这个菜单卸载；只在小米客户端里删除，插件可能会自动恢复。手动指定账号等用法见[进阶说明](../docs/plugin-installation.md)。

## 注意事项

- NAS 存储池需已挂载，目标用户需在小米客户端完成初始化；远程安装需能使用 root SSH 登录。
- 安装时需要联网获取并校验 ARM64 下载内核；普通下载和 BT 分别使用两个核心。
- 当前支持 BT v1 及兼容的混合种子，纯 BT v2 暂不支持。磁链需先取得元数据；失败重试能否续传取决于资源和服务端。
- 仅移除任务或清空记录不会自动删除文件；勾选“同时删除已下载和未完成文件”会删除对应文件，确认前仔细核对。
- 外部管理接口只对可信局域网开放并使用认证，不要转发到公网。aria2 暂不支持 WebSocket；HTTPS 页面接入需匹配的 HTTPS 反向代理。
- Openlist 兼容接口不是 qBittorrent 原生 WebUI，也不是 BT 入站端口。外部客户端直接控制核心可能操作其余客户端任务，相关任务不一定显示在插件列表。
- 内核更新会短暂重启当前用户的下载服务，可能中断共用核心的外部下载；卸载保留已下载和未完成文件。
- 使用安装脚本卸载会取消本插件的自动恢复登记；仅在应用市场删除时，恢复服务可能将插件补回。

- 关闭插件页面不会停止后台服务；通过页面主动停止后，恢复检查不会擅自重新启动。
- 下载服务由系统独立托管，核心异常退出会自动重启；无需每分钟访问插件源码保活。空闲锁操作不再产生可写关闭事件，但实际下载、做种、日志或其他应用仍可能影响硬盘休眠。
- 内核更新和回滚同样经过系统服务管理；空闲或全部暂停时降低同步频率，活动任务保持及时刷新。运行日志按大小轮转并限制保留份数。
