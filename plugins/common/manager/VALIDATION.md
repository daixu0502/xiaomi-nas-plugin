# 统一安装器本地与真机验收记录（2026-10-30）

本记录对应管理引擎 2.0.5、恢复组件与更新组件 2.0.0、公共权限组件 1.3.2。
已完成用户授权的 NAS 切换、重启复验、彻底卸载、共用组件清理和断网全新安装。本记录描述当时的真机验收；后续目录整理与升版发布另见[仓库发布记录](../../../docs/repository-layout.md)。
隔离测试中的原厂命令及 systemd 使用模拟边界，真机结果单独记录，不以模拟结果替代。

## 数据策略

- `reinstall`（含首次整机切换）和 `update` 保留配置、任务、插件设置、更新内核与原启停意图。
- 普通 `uninstall` 提交后删除当前账号插件拥有的配置、任务、断点、缓存、专属受保护数据、恢复快照和更新记录；成功完成不保留回退备份。
- 固定锁 inode 和卸载标记不作为业务数据清除。删除中断时保留已提交事务，开机或下次维护继续删除，不重新恢复插件。
- 独立 SSH 工具与登录配置、Docker 容器／镜像／卷、用户下载与媒体文件不属于插件卸载范围。

最终设备处于**全新安装**状态，原插件配置和任务已按普通卸载规则清空；原数据仅保留于用户授权的本地维护备份。SSH 登录和独立工具没有因重新安装插件而重新配置。

本次真机发现并修复的问题：

- 固件控制脚本的设备号导致 `os.path.ismount()` 误判；改用内核挂载表，在遍历前拒绝真实挂载点。首次失败事务实际回退成功。
- 任务中心、设备中心的内存缓存须在删除官方 tmp 链接之前释放；移除旧 Mihomo 开机 Cron，避免绕过停止意图。
- 恢复事务完成后必须启动公共事件服务；任务预约检查和维护标记发布共用权限组件锁，调度器等待维护标记删除事件，避免已登记任务的工作进程被拒绝。
- 移除 Docker 代理所需的 Docker 重启必须保存并恢复原容器启停状态。

设备不支持所尝试的按账号防火墙匹配、IPv6 filter 表及完整策略路由命令；失败尝试均撤回，最终离线验收采用网络命名空间，没有升级 NAS 系统依赖。

## 验收边界

多账号、非 pool0、六阶段故障注入、进程终止恢复、损坏包／空间不足、原厂清理和缓存删除等组合由本地隔离测试覆盖，本次未在真机另造这些场景。单插件签名更新、旧更新器拒绝和依赖下载范围已在本地验证，未发布新版本，因此未执行公网新版本页面更新。全新安装后进行了服务重启，整机重启验证发生在保留数据切换阶段。

发布仍须按用户另行授权核对远端差异。当前 Git 索引无新增内容，不含测试、缓存、密钥或设备数据；dist 仅保留清单对应的 13 份最新插件／组件／套件归档及独立 SSH 工具脚本。
