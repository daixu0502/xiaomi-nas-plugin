# 插件恢复服务 1.2.0 验证记录

验证日期：2026-10-18。维护源为本目录 recovery.py，与七插件安装包和 NAS 已安装程序一致。测试代码、真机记录及回退材料仅保留本地，不进入安装包或 Git 索引。

## 问题与修复

1. 恢复 oneshot 和 CGI 直接启动的进程仍属于调用者的 cgroup，nohup 无法隔离 systemd 的退出清理。Mihomo、快传及下载中心改由各自的 minas-plugin-<插件>-<用户>.service 托管，使用 NAS 用户身份；恢复服务只发起 systemctl 操作。
2. 启停授权精确到用户、插件与固定操作，不接受任意命令或路径。服务内部设置管理标记，避免控制脚本递归调用入口。
3. 用户主动停止独立保存为持久意图，保持插件页面可访问；恢复检查不会反向启动。原厂启动、升级、卸载钩子的临时停止不覆盖意图。明确使用 manage.sh 卸载仍取消恢复登记，并移除服务和授权。
4. 快传按当前 UID、准确脚本路径和状态目录识别进程，找回失效 PID 记录，不认领其他配置的进程；启动失败不再返回成功。
5. 任务中心增加顶部调度服务总开关和启动确认，提示已启用任务数量；总开关与单个任务开关独立。

保留 1.1.1 的缓存权限初始化、明确原厂启停日志识别、原厂摘要校验及异步启动等待。

- 28 项恢复回归通过，覆盖独立降权服务、固定 sudo 策略、手动停止意图、缓存权限、原厂卸载和状态保留。
- 3 项快传进程测试通过：无 PID 文件、过期 PID、其他状态目录隔离。
- 桌面及手机浏览器交互通过：启动确认、取消、停止、状态更新和页面宽度。模拟请求不执行任务、不修改 NAS。

## NAS 验证

- 通过真实 Mihomo/快传 CGI 停止服务，再完整执行恢复 oneshot，确认仍停止；通过 CGI 启动后再次执行恢复，确认 PID 不变。
- 实际进程 UID 为插件用户，cgroup 属于独立服务，已脱离 recovery、crond 和 fcgi-cgi 服务。
- 执行原厂 plugincenter update，真实下架卸载七插件；后台自动恢复全部插件及三个独立后台服务，再跨恢复周期确认 PID 不变。
- 任务中心通过真实 CGI 启动、停止调度器。期间只暂停任务 tick 的 Cron 行，其他 Cron 入口保留；随后恢复原 Cron 和原调度器状态。任务定义、执行记录未变化，没有执行任务。
- 七插件原厂 plugin.sh verify 和 INFO 摘要核对通过；配置、etc/var 目录、4 个任务及其启用状态、SSH 恢复材料保持。官方插件和其他用户注册信息未变。

当前版本：Mihomo 1.7.35、快传 1.1.37、任务中心 1.0.12、下载中心 1.1.14，其他插件版本不变。结束时三个后台服务运行；任务调度器保持原停用状态，4 个任务中原有 3 个启用标记保留。
