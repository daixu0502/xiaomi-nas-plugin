# 自定义持久目录

自定义组件和独立工具使用真实父目录 `/data/minas/`，由 root 拥有、0755。敏感子目录保持 0700，插件的 `etc/var` 保持各 NAS 用户拥有、0700。

| 位置 | 用途 |
| --- | --- |
| `privileged/` | 公共权限入口、模块、授权、任务和跨插件锁 |
| `plugins/data/<用户>/<插件>/` | 七插件的持久配置与状态 |
| `plugins/recovery/` | 独立恢复程序、登记和当前恢复快照 |
| `ssh/` | 独立 SSH 开机修复、应急程序及登录材料 |
| `docker/network/` | bridge/IPv6 事件维护、nft 运行库与网络事务 |
| `docker/runtime/` | Docker 29.9.2 程序、私有配置与升级事务 |
| `backups/` | Docker、权限组件及插件卸载备份 |
| `migration/` | 各工具自己的迁移记录及失败恢复材料，仅 root 可访问 |

原厂 `/data/docker`、`docker_data`、`plugin`、系统服务文件、官方插件源码和缓存保留原位。`/run` 和下载中心内存暂存保持现有策略。

每个安装包只处理自己需要的文件。更新一个插件，不要求先安装或更新其他插件，也不会搬走其他插件的数据。首次开启 SSH 的两个脚本不包含目录迁移代码。

更新插件时，先在新目录生成程序、接管当前用户的数据并建立恢复快照，校验成功后再清理它在旧共用目录中的授权、私有程序和旧快照。其他用户或插件仍在使用的文件继续保留；最后一个使用者迁走后，只清理能确认用途的旧公共文件。遇到不认识的文件会保留，不会直接删除整个共用目录。

新旧公共权限组件和恢复服务可以并存。新组件同时遵守旧操作锁，恢复服务使用各自的服务名和登记目录；定时任务切换当前用户的调度，避免同一任务被执行两次。配置、任务、密钥和原有启停设置会保留。当前插件的新旧配置冲突时会停止并保留两边数据，其他插件存在旧目录不会阻止安装。

| 独立工具 | 自动处理的内容 |
| --- | --- |
| `install-ssh-autostart-fix.sh` | SSH 开机恢复目录及恢复所需的 SSH 材料 |
| `fix-docker-bridge.sh` | Docker 网络修复目录、自己的事务和服务路径 |
| `upgrade-docker-29.9.2.sh` | 自定义 Docker 运行目录、升级事务和升级备份目录 |

独立工具只在修改操作时接管自己的旧目录，并记录失败恢复信息。迁移 Docker 运行目录时可能短暂停止 Docker 和容器；仅移动升级备份、更新插件或 SSH 工具不会因此停止 Docker。只读检查和状态查询不启动自动迁移。

Docker 镜像、容器层和卷数据不参与目录搬迁，迁移后继续使用 29.9.2。旧升级事务保留原始 JSON 及备份指纹，由固定映射解析迁移后的备份路径。只读检查示例：

```sh
python3 -B /data/minas/docker/runtime/upgrade.py --rollback-check 20261023-225226-21632746
```

默认回退保留当前本地卷；显式 `--restore-all-data` 才恢复全部备份数据。保留卷回退的原子暂存必须在 `/data/docker_data/` 的同一挂载内，不能挪到 `backups/`。

工具迁移失败会尝试恢复本工具原来的目录和服务状态；中断后再次运行同一新版工具，会先处理自己的未完成记录。排查前保留 `migration/` 和报错，不要用其他工具的旧记录覆盖当前数据。`migrate-minas-data.sh` 仍是需要配套资料的手动全局维护工具，普通安装包不再内嵌它。
