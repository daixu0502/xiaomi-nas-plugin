# 自定义持久目录

自定义组件和独立工具使用真实父目录 `/data/minas/`，由 root 拥有、0755。敏感子目录保持 0700，插件的 `etc/var` 保持各 NAS 用户拥有、0700。

| 位置 | 用途 |
| --- | --- |
| `privileged/` | 公共权限入口、模块、授权、任务和跨插件锁 |
| `plugins/data/<用户>/<插件>/` | 七插件的持久配置与状态 |
| `plugins/recovery/` | 独立恢复程序、登记和当前恢复快照 |
| `ssh/` | 独立 SSH 开机修复、应急程序及登录材料 |
| `docker/network/` | bridge/IPv6 事件维护、nft 运行库与网络事务 |
| `docker/runtime/` | Docker 29.9.2 程序、私有配置与升级事务 |
| `backups/` | Docker、权限组件及插件卸载备份 |
| `migration/` | 迁移程序、事务及失败恢复材料，仅 root 可访问 |

原厂 `/data/docker`、`docker_data`、`plugin`、系统服务文件、官方插件源码和缓存保留原位。`/run` 和下载中心内存暂存保持现有策略。

新安装包和独立 SSH、Docker 工具自带离线自动迁移组件。全新 NAS 直接建立新目录；安装、更新或修改服务时检测到旧目录，先迁移设备上实际存在的组件，再继续原操作，无需单独下载迁移包，也不要求七插件全部安装。只读检查、状态查询和安装预览不会启动迁移。

迁移在独立的临时 systemd 服务中执行，停止旧恢复服务或安装连接中断不会终止协调器。按原目录 inode 改名，更新持久链接、CGI/sudoers、cron、systemd、独立程序及恢复快照。保留其他已安装插件的版本、配置、任务、密钥和原启停意图。旧恢复快照中尚有待恢复插件时，先调用旧恢复服务恢复，再迁移其源码和数据。涉及旧自定义 Docker 运行目录时会协调短暂停止 Docker 和容器；只有插件或 SSH 数据时不停止原厂 Docker。迁移期间保留持久维护保护和独立 SSH 过渡入口，不通过符号链接重定向受保护目录。

同一数据根的新旧目录同时存在时，停止安装并保留两边数据，不自动合并覆盖。迁移失败会自动恢复原布局；断电等中断后再次运行新安装入口，会先依据持久事务恢复，再重新迁移。已经完成迁移时重复安装不再搬迁。源码校验异常、同一插件的多用户版本不同或旧自定义 Docker 正处于未完成事务时，停止迁移并报告具体原因。

Docker 镜像、容器层和卷数据不参与目录搬迁，迁移后继续使用 29.9.2。旧升级事务保留原始 JSON 及备份指纹，由固定映射解析迁移后的备份路径。只读检查示例：

```sh
python3 -B /data/minas/docker/runtime/upgrade.py --rollback-check 20261023-225226-21632746
```

默认回退保留当前本地卷；显式 `--restore-all-data` 才恢复全部备份数据。保留卷回退的原子暂存必须在 `/data/docker_data/` 的同一挂载内，不能挪到 `backups/`。

迁移未完成时不要删除 `migration/`、移动根目录或手动启动被保护的服务。保留终端显示的迁移编号，可在 NAS root 终端使用持久迁移程序的 `--rollback <迁移编号>` 恢复原布局。已经提交成功的迁移不能用旧事务覆盖后续用户数据。
