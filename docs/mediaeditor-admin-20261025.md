# 影视编辑 1.1.0：重复代码、关联重分配与管理员全库修复

默认范围仍为自有且未共享的记录；管理员可显式开启跨账号全库范围，服务器读取 NAS 账号的管理员资格，并在执行、回退时重新核验。普通用户不能使用全库模式或全库扫描。

## 代码冲突

保留官方 `UNIQUE(midb_id)` 约束。用户取消了强制覆盖和重复代码写入需求，当前只显示冲突影片名称、年份及本地编号，并提供放弃当前草稿、前往编辑冲突影片的入口；涉及其他账号或共享记录时明确进入管理员全库模式。保存时再次检查，防止并发占用绕过前端提示。

## 官方关联删除行为

重分配先添加目标关联，再删除原关联，使用真实官方 `file_media` 触发器。官方删除关联会移除原影片的部分观看/收藏记录；原影片引用数归零时会删除原影片。实际变化先在 root 保护的完整数据库副本中演算，展示删除的记录数量、影片及关联，确认后才备份、事务写入。文件库检索可选择无关联文件，也可替换所选文件的现有影片关联；不执行物理文件删除。

## 全库修复

支持扫描并逐项选择修复：影片/文件引用计数，失效系列，无效季集号，关系表中的失效外键，上次观看文件与影片不匹配，官方搜索索引缺失、过期或多余条目。扫描仅生成保护目录内的参考结果，不修改业务数据；预览仍运行官方触发器，所以会把额外发生的观看记录等删除一起列出。

每次最多预览 200 项，问题列表最多展示 500 项，修复后可继续扫描。无关联影片保留，可在全库模式编辑或重新分配文件。没有任意 SQL、任意系统命令、表结构重建或移除唯一约束入口。

## 一致性与回退

结构操作固定适配已检查的官方 schema 指纹。扫描、演算与执行都核对状态；写入在 `BEGIN IMMEDIATE` 中再次比较全库逻辑指纹，和预览不一致就拒绝执行。每次写入前生成 WAL 一致性备份，回读结果必须匹配预演结果，数据库不能出现未预计的新外键错误。

回退只恢复原操作的实际记录差异，先检查相关记录、关联和观看状态没有后来变化。恢复过程中临时关闭当前连接的普通触发器，避免二次连带删除，完成后恢复；官方触发器定义及表结构不变。修复回退需要恢复已记录的旧外键错误时，预览明确告知，且仅允许恢复历史计划中已记录的错误。备份、预览、扫描参考及修改历史沿用 `/data/minas/plugins/mediaeditor/` 保护目录。

本地测试代码、演算数据库和部署资料不上传，不打进安装包；不替用户对真实媒体记录执行重分配或修复。
