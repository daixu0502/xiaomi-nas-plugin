# 影视保护数据归位与持久目录链接兼容

影视编辑将旧 `/data/minas/plugins/mediaeditor/<用户>/` 移到 `/data/minas/plugins/data/<用户>/mediaeditor/protected/`。目标与用户所属的 etc/var 平级，目录 root:root 0700、文件 0600；所有上级保持 root 所有且普通账号不可写。多账号共享写锁迁至 `/data/minas/privileged/modules/mediaeditor/var/write.lock`，保持同一 inode。官方媒体库位置不变，迁移不执行媒体修改。

protected 是权限边界，不是必须使用的目录名称。普通 etc/var 由插件账号管理；账号对父目录有写权限时，可以替换其中的 root 文件或子目录。修改计划会驱动 root 数据库操作，备份可能包含跨账号记录，参考结果也会参与后续修改，因此保留在 root 控制的平级目录。若放进 etc，仍需增加独立的保护父目录和路径校验，不能作为普通用户配置读写。

迁移仅由 root 安装器执行，先取得现有公共权限组件独占锁并排空编辑调用，再锁定原写锁。安装迁移记录持久保存于模块 var，验证所有原记录的权限、哈希、设备及 inode 后同文件系统重命名；冲突拒绝覆盖，异常回退，未完成记录可继续执行。API 在旧数据或旧锁未迁完时拒绝编辑。安装、状态接口和卸载说明同步新位置；卸载保留账号 protected 内的备份与历史。无需为此增加提权入口或新的公共组件版本。

下载中心“清理磁链缓存”和删除任务的元数据清理原先对官方 var 链接使用 O_NOFOLLOW，迁移为链接后出现 ENOTDIR。修复改为校验官方持久目录目标、按组件逐级无链接打开，再以目录 FD 访问 metadata。只允许固定账号/插件对应的官方链接；metadata 及任务子目录仍拒绝符号链接，不放宽任意路径。BT 种子缓存列表、预览和删除复用同一入口，继续禁止 root 访问用户缓存。

清理中的核心任务占用判断同时识别官方链接路径和规范路径，保护数据库未登记的核心磁链任务；qB 磁链重试也兼容同一状态目录的规范路径。已有记录的所有任务状态仍受保护，不清理下载内容、用户导入种子和续传材料。

计划任务清理的范围检查修正为识别当前账号的规范 var 路径。etc、protected、其他账号及任意链接跳转仍不在允许范围。其余 Docker、Mihomo、控制中心、SSH 恢复、快传的存储读取或缓存入口已核查：普通 Path 读写本就兼容链接，敏感缓存先降权再校验官方 tmp，未发现同类直接拒绝 etc/var 的调用。共享工具副本同步到 Mihomo/快传；它们的运行目录行为未变。

本地回归使用隔离目录、数据库和模拟下载核心，覆盖多账号迁移、文件及锁 inode 保持、冲突回退、中断恢复、重装、目录替换、非法链接、任务保护、核心规范路径和清理权限边界。测试源码及实例报告保持本地，不进入 Git 索引或安装包。
