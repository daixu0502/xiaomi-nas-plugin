## 已实施

| 部分 | 行为 |
| --- | --- |
| Docker 计数 | 顶部运行／停止计数与容器列表来自同一次容器采样；迟到的概览响应不能覆盖它。手动刷新和窗口内自动刷新都会更新列表与计数。 |
| Docker 升级 | 有健康检查时必须达到 healthy；按照 StartPeriod、Interval、Timeout、Retries 计算等待预算，限制在 60–600 秒。无健康检查时只验证持续运行，并明确提示范围。验证前保留旧容器。 |
| Docker 恢复 | root 私有目录保存原始容器检查结果与提交标记，阶段变化时原子写入并同步文件及父目录；中断事务在开机、后续变更操作或升级状态查询时恢复。仅移除带本次事务标签的替换容器，恢复原名称、端点参数、网络及运行／停止／暂停状态。回退容器不回退数据卷。 |
| 快传覆盖与资源限制 | 同目录临时文件完整写入、fsync 后使用不覆盖的硬链接提交，重名继续选择后缀，响应返回实际名称。最多 32 个连接、8 个活动传输、2 个目录压缩；60 秒读取空闲超时。断流清理本次临时文件，分享令牌和请求查询参数不进入普通日志。 |
| 请求生命周期 | 八插件使用共享读取超时、取消和定时器归属管理；隐藏时暂停读取，卸载后不再派发请求，丢弃关闭／隐藏前的旧读取结果。已发出的写事务继续，超时不自动重提。 |
| 下载后台 | 启动载入配置和任务索引；inotify 监听固定文件名，挂载变化触发重载。无变化时仅使用内存参数查询本机核心，采样写入真实 tmpfs。复用 HTTP 客户端，避免每次采样重新读取证书。 |
| 下载持久化 | aria2 禁止无条件定时保存会话，队列／状态变化和停止时保存。配置、任务库、aria2 会话、qB 配置及 BT_backup 保持持久存储，真实下载使用各自持久目标。 |
| qB 空闲容量查询 | 核心自身每 30 秒查询默认路径。插件和 Openlist 入口均提供明确的持久目标；未指定目标的隐式回退指向 root 创建的不可写空内存目录，里面不存放下载、缓存或断点，避免空闲扫描持久目录。 |
| 调度与 SSH 清理 | systemd 事件进程按下一次任务到期／密钥到期等待；配置、前置执行结果、挂载、时钟变化触发重算。移除每分钟任务遍历和 SSH prune Cron，保留原执行标记、任务重试和停止意图。入口瞬时错误最多重试三次；领取临时密钥仍即时检查过期。 |
| 状态与 UI | 控制中心重启后复核实际状态；下载核心用认证 RPC 确认可用性，分别报告监督进程、两个核心与同步健康。Docker 失败按钮恢复、影视搜索忽略过期上下文、历史展示备份数量／占用，Mihomo 清理已触发定时器。 |
| IPv6 路由事件 | RA 续期、路由及链路通知仅处理 /proc 内核状态，不重复读取持久配置或启动 Docker/nft/ip。真实 Docker 网络及专用防火墙表变化仍触发完整恢复。 |
| 运行位置 | 下载中心官方 tmp/runtime 使用 96 MiB 上限 tmpfs；快传、Mihomo 各 24 MiB。容量为上限。root 通过降权校验目录并传递文件描述符后挂载，不将持久材料迁入内存。另修复 Mihomo 安装暂存目录和替换配置后的属主处理。 |

qB 行为核对使用对应版本官方实现：[会话计时与仅变更后保存](https://github.com/qbittorrent/qBittorrent/blob/release-5.3.0/src/base/bittorrent/sessionimpl.cpp)、[断点变更判断](https://github.com/qbittorrent/qBittorrent/blob/release-5.3.0/src/base/bittorrent/torrentimpl.cpp)、[默认目录容量查询](https://github.com/qbittorrent/qBittorrent/blob/release-5.3.0/src/base/utils/fs.cpp)。真机进一步确认：DHT／协议流量也会使累计统计变脏，不能仅依赖 dirty 判断；因此设置 SaveStatisticsInterval=0，正常停止时仍保存累计计数。异常断电可能丢失本次运行未保存的累计流量统计，配置、任务与断点保存不受影响，保留活动任务所需的核心断点机制。
